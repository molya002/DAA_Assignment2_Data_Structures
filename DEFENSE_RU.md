## Как устроены структуры

**DynamicArray:** `size` — число элементов, `elements.length` — вместимость. При заполнении создаём массив вдвое больше и копируем элементы. `get` сразу обращается по индексу. Вставка в середину сдвигает суффикс вправо; удаление — влево. В contains возвращаем true при первом совпадении.

**MyLinkedList:** Node хранит int и ссылку next. head указывает на первый узел, tail — на последний. Добавить в конец можно за O(1), но удалить последний узел нельзя за O(1): нужно найти предпоследний. get(i) проходит i ссылок. При удалении единственного узла обнуляются head и tail.

**MinHeap:** это полное бинарное дерево в массиве. Дети индекса i: 2i+1 и 2i+2, родитель: (i-1)/2. Для каждого ребра родитель не больше ребёнка. При insert значение поднимается, пока меньше родителя. extractMin сохраняет корень, переносит последний элемент наверх и опускает его через меньшего ребёнка. Равные элементы менять не нужно.

## Частые вопросы

**Почему append массива амортизированно O(1)?** При росте копируем 8+16+32+... элементов. Геометрическая сумма линейна по общему числу добавлений, поэтому в среднем по последовательности на одну операцию приходится константа. Это не означает, что каждая вставка имеет O(1).

**Почему худшая вставка в эту кучу O(n)?** При заполнении копируется весь массив. Сам bubble-up — O(log n); худшая амортизированная стоимость вставки с учётом роста — O(log n).

**Почему одинаковая Big-O не даёт одинаковое время?** Big-O описывает рост, а не цену одной операции. Последовательные int находятся рядом; узлы — отдельные объекты. Переход к следующему адресу зависит от чтения предыдущего. Заголовки объектов и выравнивание увеличивают память.

**Что такое инвариант?** Утверждение, верное перед каждой итерацией. Для contains: в уже проверенном префиксе искомого значения нет. Для удаления: обработанная часть уже сдвинута на одну позицию, необработанная ещё хранит исходные значения. Надо объяснить начало, сохранение и завершение, включая ранний return.

**Почему пять запусков и медиана?** JVM компилирует горячий код, ОС переключает задачи. Прогрев уменьшает начальные эффекты, медиана меньше зависит от одиночного выброса. Полностью шум не исчезает; особенно осторожно сравниваем короткие замеры.

**Почему у списка get(0) ноль steps?** Определение steps учитывает переходы next, а не всю работу CPU. Чтение head и значения узла всё равно требует постоянного времени. W3 у списка не нулевой: изменения head/tail/next учитываются в moves.

**Почему Floyd O(n), а не O(n log n)?** Большинство узлов близко к листьям и опускаются мало. Складываем количество узлов каждой высоты, умноженное на её высоту; сумма линейна. Цикл начинает с последнего родителя и идёт к корню, поэтому поддеревья детей уже являются кучами.

**Почему bonus содержит descending и random?** При убывающих значениях новый минимум проходит до корня: суммарно Θ(n log n). Для случайного порядка средняя длина подъёма ограничена константой, поэтому нельзя обещать асимптотическое ускорение Floyd на любом входе.

**Что показывает JOL?** Размер всех объектов, достижимых из структуры: сама структура, узлы/массив и объект Metrics. В текущей JVM узел занимает 24 байта, а одно значение int в массиве — 4. У массива есть запас capacity; память не уменьшается после remove.
